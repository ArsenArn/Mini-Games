# Loop Lab — Switch Junctions

Локальный TypeScript + Vite + Canvas прототип: 10 уровней, English UI, два связанных конвейера и двусторонние контейнеры. Без backend и платных сервисов.

## Запуск

Node.js 22 LTS или новее. PowerShell:

```powershell
cd "C:\Users\arsen\Documents\WEB GAMES\Loop Sort Switch Junctions"
npm.cmd install
npm.cmd run dev
```

Открой адрес из терминала, обычно http://127.0.0.1:5173/. Остановка: Ctrl+C. В среде без блокировки npm.ps1 также работают `npm install` / `npm run dev`.

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run solve
npm.cmd run analyze
```

Сборка — `dist/`; открывать через HTTP, не file://. Для телефона в своей Wi-Fi сети: `npm.cmd run dev -- --host 0.0.0.0`, затем IP компьютера с указанным портом. Физический телефон не проверялся.

## Компактный интерфейс

Название текущего уровня — кнопка выбора. Тап/клик открывает список всех десяти уровней поверх поля, не меняя его размеров. Текущий пункт выделен. Выбор загружает уровень и закрывает меню; Escape и клик снаружи тоже закрывают его. Поддержаны стрелки клавиатуры, Home/End и Enter. Длинный список прокручивается внутри меню.

Поле занимает оставшуюся высоту `100dvh` с safe-area отступами. ResizeObserver подбирает максимальный размер с пропорцией 420×640. Canvas, эффекты и расположенные над контейнерами кнопки масштабируются вместе; игровые координаты и скорость не меняются. Постоянной панели десяти карточек больше нет.

Pause, Restart и ×1/×2/×4 постоянно находятся под полем. «Rules & Lab» открывает отдельное окно с правилами, AUTO/MANUAL, DEBUG и ручным поворотом. В MANUAL дополнительная кнопка «Turn» доступна в верхней панели после закрытия окна. Окно закрывается крестиком, Escape или кликом по фону. Прокрутка правил/DEBUG происходит внутри окна, а не на игровой странице.

На 1920×1080, 1366×768, 390×844 и 360×640 все уровни помещаются без горизонтальной и вертикальной прокрутки. Все контейнеры видны; области контейнеров, выбора уровня и основных нижних кнопок не меньше 44 px. Это проверка браузера и touch-эмуляции; поведение реальных мобильных панелей/вырезов и FPS устройства отдельно не проверялось.

## Правила

Один успешный тап по непустому незакрытому контейнеру выпускает ровно один крайний блок у ленты. Белая рамка показывает доступный блок. Повторные выпуски разрешены, пока есть блоки и свободное место на конвейере.

Контейнер автоматически принимает проходящий блок, если не закрыт, имеет свободное место и пуст либо крайний цвет совпадает. Блок вставляется на тот же доступный край. Возврат в исходный контейнер разрешён после настоящего обхода точки обмена; немедленного обратного приёма в точке выпуска нет.

Полный одноцветный контейнер закрывается крышкой и ✓, перестаёт принимать и выпускать. Победа — все контейнеры закрыты и лента пуста. Верхний счётчик показывает число движущихся блоков / вместимость ленты. Количество каждого цвета сохраняется.

Два исходных кольца движутся против часовой стрелки. Каждый общий узел имеет один выбранный выход для любого входящего блока:

| Route | N1: входы A1/B1 | N2: входы A0/B0 |
|---|---|---|
| GREEN | A0 | A1 |
| YELLOW | B0 | B1 |

В AUTO успешный ручной выпуск переключает обе стрелки. Приём, тап по пустому/закрытому контейнеру и отказ по вместимости ничего не переключают. Выход читается в момент достижения узла; положение ранее выпущенных блоков при переключении не меняется.

Активный маршрут обозначен кромкой и мягкой подсветкой. На пересечении он изображён сверху с разрывом нижней ленты и тенью. Одна компактная красная стрелка показывает выход; редкие полупрозрачные шевроны движутся по ленте. Цвет маршрута не ограничивает цвета грузов.

Шесть возможных цветов дублируются символами: коралловый ●, синий ◆, зелёный ▲, жёлтый ✦, фиолетовый ■, бирюзовый ✚. На каждом уровне используется только нужное подмножество.

**Уровни 01–04 и 06 сохранены без изменений**, включая исходные последовательности, точки обмена и начальные стрелки. Это проверено сравнением конфигураций и отдельными тестами.

Уровни 05, 07–10 имеют ровно заданные параметры. Каждый используемый цвет встречается ровно Depth раз, все начальные контейнеры смешанные, завершённых стопок нет. Для 5/6 цветов добавлены фиолетовый и бирюзовый. Контейнеры распределены по верхней/нижней внешней границе существующих петель и соединены с настоящими точками обмена.

Уровень 7 остаётся Hard: три цвета, но глубина четыре, длинные взаимозависимые последовательности и повторные перенаправления. В найденном примере при 40-секундных ожиданиях нужно 13 выпусков; у защищённого уровня 6 — 9. Уровни 8–10 требуют работы с более глубокими/многоцветными очередями и ограниченным общим буфером. Метки сложности — дизайнерская и моделируемая оценка, не доказанная сложность для людей.

## Решатель и оценка сложности

`npm run solve` заново ищет реальные решения через `release()` / `step()`. Состояния поиска разделяют неизменяемую геометрию и копируют только изменяемые данные — это устранило избыточное потребление памяти. Для шестиконтейнерного уровня применяется взвешенный поиск с приоритетом сортировки; для остальных — ограниченный BFS. Оба используют абстракцию состояний после ожидания, поэтому не доказывают полноту или глобальный минимум ходов. Любой найденный ответ отдельно воспроизводится обычной симуляцией.

`tests/solutions.ts` содержит только свидетельства тестов: игра их не импортирует, не проверяет «правильный порядок» и не запрещает другие ходы. Изменения решателя не меняют игровые правила.

`npm run analyze` обновляет [JSON](reports/level-analysis.json) и [краткую таблицу](reports/level-analysis.md): seed 20261029, 400 случайных серий на уровень, ожидания 20/40/80 секунд и ограниченный бюджет ходов. Сохраняются найденные решения, заполнение ленты, перенаправления, успешные/неуспешные серии, тупики и уникальные найденные порядки. Это модель, не win rate игроков и не число всех возможных решений. Сложность поздних уровней требует живого плейтеста.

## Скорость и архитектура

Симуляция и Canvas используют общую геометрию по длине дуги из `src/routeGeometry.ts`. Базовая скорость — 64 единицы поля/с; в экранных CSS px/s она умножается на выбранную скорость и `canvasWidth / 420`. При изменении viewport меняется только масштаб картинки. DEBUG показывает измеренную скорость и её экранный эквивалент; на паузе — ноль.

- `src/levels.ts` — конфигурации, палитра, очереди и размещение точек обмена.
- `src/routeGeometry.ts` — неизменённые формы петель, общие узлы и длины дуг.
- `src/boardLayout.ts` — контейнеры возле тех же путей.
- `src/simulation.ts` — прежние правила. В этой итерации расширен только подсчёт цветов на шесть; тела правил выпуска, приёма, закрытия, маршрутизации, победы и движения не менялись.
- `src/renderer.ts` — прежний визуал, эффекты и анимация.
- `src/main.ts`, `src/style.css` — меню, fit по оставшейся высоте, управление и окно лаборатории.
- `tests/balance.test.ts`, `tests/protected-balance.ts` — новые параметры и защищённые уровни.
- `tests/layout.test.ts`, `tests/speed.test.ts`, `tests/simulation.test.ts` — геометрия, скорость и правила.
- `tests/search.ts`, `scripts/analyze-levels.ts` — инструменты проверки, не часть игровой сборки.

## Ограничения

Известных блокирующих проблем в проверенных размерах нет. Реальные мобильные браузеры, safe-area устройства и FPS физического телефона не проверялись. Окна меню и правил могут прокручиваться внутри себя; игровая страница на заданных размерах не прокручивается.

Нет физики столкновений/разделения сегментов: быстрые выпуски могут наложиться визуально, оставаясь отдельными логическими блоками. Неверные ходы могут заполнить ленту без доступного приёма и потребовать Restart — это прежнее последствие вместимости, а не обязательный тупик проверенных прохождений. Нет undo, сохранений и метапрогрессии.

Предыдущая версия сохранена в `.local/before-compact-balance/`. Исходные изображения и видео не изменены.
